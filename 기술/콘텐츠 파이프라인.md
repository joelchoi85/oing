# 콘텐츠 파이프라인

## 결론: 판마다 그 자리에서 AI 로 만들지 않는다
- 휴대폰에서 이미지 생성은 느리고(수십 초~분), 기기마다 결과가 다르며, **틀린 판(찾을 수 없는 차이, 그림을 망친 편집)을 걸러 낼 수 없다**.
- 그래서: **개발 PC 에서 미리 대량 생성 → 자동 검증 → 사람 확인 → 콘텐츠 묶음으로 배포**. 게임은 그림 + JSON 만 읽는다(완전 오프라인).

## 1. 명화 수집과 라이선스
- 출처는 **저작권 없는 이미지(CC0 또는 퍼블릭 도메인 마크 PDM)로 공개한 기관만** (PDM 도 됨, Joel 10-28): The Met Open Access, Rijksmuseum, Art Institute of Chicago, National Gallery of Art(워싱턴), Cleveland Museum of Art, Smithsonian Open Access, Paris Musées 등.
- 그림마다 **출처 기록**(`content/paintings/<id>.json`): 제목, 작가, 연도, 소장처, 소장 번호, 원본 URL, 라이선스 URL, 받은 날짜. 게임의 명판·크레딧에 그대로 쓴다. 기록이 없으면 빌드에 못 들어간다(검사 스크립트).
- 고르는 기준: 원본 비율 그대로(자르지 않음, 화면이 세로·가로 둘 다), 세부가 많을 것(숨은·다른 그림에 유리), 종교·폭력·나체는 연령 등급 기준에 맞춰 따로 표시.

## 2. 판 만들기 (개발 PC, mflux 등 로컬 모델)
### 다른 그림 찾기
1. 그림은 원본 비율, 긴 변 2048px 정도로 줄인다.
2. **바꿀 곳 후보**를 고른다: 사물 분할(SAM 등)로 물체 마스크 → 너무 작거나 큰 것, 얼굴은 제외.
3. 후보마다 편집 종류를 정하고(사라짐·색·모양·생김·이동) **그 영역만** inpaint/edit — 화풍 유지 프롬프트.
4. 편집본을 원본에 **그 마스크 안만** 붙인다(마스크 밖은 원본 픽셀 그대로 → 엉뚱한 차이가 생기지 않는다).
   - 실제 도구: `tools/auto_diff.sh <그림 id>` = Bonsai-2 27B 기획 → FLUX.3 klein 상자 편집 → 바뀐 곳만 붙이기(`paste_edit.py`) → 휴대폰 보임 정도로 5개 고르기. 이유는 결정 로그 2026-10-22.

### 숨은 그림 찾기
1. 시대·장면에 어울리는 물건 목록(정물: 안경·열쇠·골무 / 풍경: 연·새장·우산…).
2. 놓을 자리 후보: 질감이 복잡하고 물건 크기 비율이 맞는 곳.
3. 그 자리 크롭에 "이 화풍으로 ~를 그려 넣어" 편집 → 원본과의 차이로 물건 마스크를 따낸다(Dear Sphere 의 `paint_in.py` 방식).

## 3. 검증 (자동, 결정론) {#검증}
판마다 `verify_*.py` 가 **통과/불합격 + 난이도 점수**를 낸다. 불합격은 버린다.

| 검사 | 다른 그림 | 숨은 그림 |
|---|---|---|
| 개수 | 원본·편집본 차이 덩어리 수 = 정답 수 | 물건 마스크 수 = 목록 수 |
| 새는 곳 | 정답 영역 밖 차이가 문턱 이하 | 물건 밖 변화 없음 |
| 크기 | 정답 하나 면적이 화면의 0.2~3% | 물건이 손가락으로 누를 만큼(최소 40dp 원) |
| 간격 | 정답끼리 최소 거리 | 물건끼리 겹치지 않음 |
| 보이는가 | 차이 영역의 대비·색차가 문턱 이상 (너무 미세 = 불공정) | 물건 실루엣이 알아볼 만한가: 로컬 VLM 에 "이 영역에 ~가 있나?" 질문 |
| 너무 쉬운가 | 대비가 너무 크면 '쉬움'으로만 | 배경과 색이 너무 다르면 '쉬움'으로만 |

- **난이도 점수** = 면적·대비·주변과의 색 비슷함·위치(가장자리일수록 어려움)를 섞은 수. 구간으로 쉬움/보통/어려움.
- 판 JSON: `{painting, mode, regions: [{id, polygon, kind, label}], difficulty, seed, verified_by}`. 정답 판정은 게임 안에서도 같은 다각형으로(점 ∈ 다각형).

## 4. 사람 확인
- 자동 통과한 판만 **확인 화면**(로컬 웹 또는 Godot 도구 장면)에서 넘겨 보며 ✓/✗. 한 판 10초.
- 확인 기록은 판 JSON 의 `verified_by` 에. 사람 확인 없는 판은 리더보드 판(그날의 그림)에 못 쓴다.

## 5. 배포
- 앱에 기본 묶음(그림 30점 × 모드) 포함 → 첫 실행부터 오프라인.
- 추가 묶음은 **Cloudflare R2**(내보내기 트래픽 무료)에서 받는다. 묶음 = 그림 webp + 판 JSON + 출처 JSON, 해시로 무결성 확인.
- 그날의 그림 일정표도 묶음에 미리 넣는다(서버 없이도 "오늘 판"이 정해짐). 서버는 리더보드에만.

## 6. 직소는 생성이 필요 없다
- 그림 + 조각 수 + 씨앗이면 조각 모양이 결정된다([실물 퍼즐 표현](../기획/실물%20퍼즐%20표현.md)). 그림 수만큼 바로 판이 생긴다.
