# 네트워크 — 최소 비용

## 원칙
1. **혼자 하기는 서버가 전혀 필요 없다.** 네트워크가 없어도 모든 판이 된다.
2. 협동은 **가능하면 P2P**(기기끼리 직접) — 서버를 거치지 않으면 비용이 0이다.
3. 서버(Cloudflare Workers)는 **방 찾기·연결 중개·리더보드**만. 게임 중 메시지 중계는 P2P 가 안 될 때의 대비책.
4. 메시지는 **사건(event)** 위주로 보내고, 화면의 부드러움은 받는 쪽 **보간**으로 만든다.

## 연결 방식 두 가지

### A. 근처(같은 Wi-Fi) — 서버 0
- 같은 공유기면 **UDP 브로드캐스트로 서로를 찾고**(방 이름 광고) Godot `ENetMultiplayerPeer` 로 직접 연결. 인터넷도 필요 없다.
- 방장(host)이 판의 권위자: 조각 잠금·충돌 판정은 방장이 정한다.

### B. 온라인 — Cloudflare Workers
- **방 = Durable Object 하나**(방 코드 6자리 또는 초대 링크). 들어오면 WebSocket 으로 붙는다.
- 1단계(시그널링): 방 DO 가 WebRTC offer/answer/ICE 만 넘겨 준다 → 성공하면 **WebRTC 데이터 채널로 P2P**. 그 뒤 DO 는 거의 일하지 않는다(연결 유지 확인만).
  - STUN 은 공개 무료 서버. TURN(대칭 NAT 대비)은 비용이 생기므로 쓰지 않고 2단계로 넘긴다.
- 2단계(중계 대비책): P2P 가 실패하면 **같은 DO WebSocket 으로 중계**. 이때만 메시지 수가 비용이 된다 → 아래 '보내는 양 줄이기'를 엄격하게.
- DO 는 **WebSocket Hibernation API** 로 — 메시지가 없을 때 잠들어 시간 요금이 안 붙는다.
- 판 상태 저장: DO 내장 SQLite(늦게 들어온 사람에게 현재 판 전달, 끊겼다 다시 들어오기).

### 무료 한도 (최신 단가·월 비용은 서버 비용 예상)
| 서비스 | 쓰는 곳 | 무료 한도(대략) |
|---|---|---|
| Workers | 방 만들기·리더보드 API | 하루 요청 10만 |
| Durable Objects | 방(시그널링·중계·판 상태) | 무료 플랜에서 SQLite DO 사용 가능, 하루 요청·시간 한도 있음 |
| D1 | 리더보드 | 하루 읽기 500만 행, 쓰기 10만 행 |
| R2 | 콘텐츠 묶음 | 저장 10GB, 내보내기 트래픽 무료 |
→ 대부분 P2P 로 빠지면 DO 요청은 "방당 수십 건"이라 무료 한도로 꽤 오래 간다. 중계 비율을 대시보드로 지켜본다.

## 협동 직소 동기화 {#협동 직소 동기화}
### 무엇을 보내나
| 메시지 | 언제 | 내용 |
|---|---|---|
| `grab` | 조각(덩어리)을 집을 때 | 조각 id, 사람, 시각 |
| `path` | 끄는 중, **띄엄띄엄** | 위치 몇 개 묶음 (아래) |
| `drop` | 놓을 때 | 조각 id, 최종 위치·회전, 붙었으면 붙은 덩어리 |
| `flip`/`rotate` | 뒤집기·돌리기 | 조각 id |
| `snapshot` | 들어올 때 한 번 | 판 전체 (조각 위치·덩어리) |
- 잠금: `grab` 은 권위자(방장 또는 DO)가 순서대로 받는다. 이미 잡힌 조각이면 거절 → 그 사람 화면에서 조각이 흔들리며 내려감.

### 움직임을 얼마나 보여 줄까 — 세 단계
1. **P2P 연결일 때(무료)**: 끄는 동안 15Hz 로 위치를 보낸다. 받는 쪽은 **100~150ms 늦게 재생**(지터 버퍼)하며 두 점 사이를 **lerp**(또는 Catmull-Rom 으로 곡선)로 잇는다 → 실제 손 움직임 그대로.
2. **중계일 때(유료 메시지 아낌)**: `grab` + `drop` + **경로 요약**만.
   - 끄는 동안 위치를 0.25초마다 **모아 두었다가**(4Hz 샘플) **1초에 한 번 묶음으로** 보낸다 → 메시지 1개에 점 4개.
3. **경로 없이 놓기만 올 때(최소)**: `grab` 순간 그 조각이 "들린" 모양(그림자·떠오름) + 그 사람 색 테두리로 표시, `drop` 이 오면 집은 자리 → 놓은 자리로 **곡선 궤적(베지어, 위로 살짝 볼록)** 을 0.3~0.5초에 **ease-out** 으로 날아가게. 손이 옮긴 것처럼 보인다.
- 세 단계는 연결 상태에 따라 자동으로 고른다. 받는 쪽 코드는 하나(시간표가 붙은 점 목록을 재생)로 통일 — 1·2·3단계는 점의 개수만 다르다.

### 대략 메시지 수 (2인, 150조각, 30분)
- 조각 놓기 ≈ 300회 × (grab + drop) = 600
- 합 ≈ 1,200 메시지/판 (중계일 때). 1단계(P2P)는 서버 메시지 ≈ 시그널링 수십 건뿐.

### 숨은·다른 그림 협동
- `found(region id, 사람)` 하나만. 서로의 커서는 보내지 않는다(필요 없음). 메시지 수가 판당 10개 안팎.

- **공개 목록**: 방장이 방 정보를 글 프레임 `room` 으로 서버에 알린다(`Coop._publish`, 바뀔 때만). 방 DO 가 D1 `rooms` 를 고치고, 방장이 나가면 지운다. `GET /rooms?game=`(로그인 없이, 30개, 게임 중·꽉 찬 방 제외), 방 참여 화면을 보는 동안 8초마다. 비공개 방도 '(비공개)'로 보이고 눌러서 비밀번호를 낸다. 숨은 방은 찾을 길이 없어서다. 방 번호(4자리)는 목록이 쓰고 사람에겐 안 보인다. 방 이름·판 글은 서버가 가릴 말을 거르고, 줄 옆 '신고'는 서버가 방장 계정을 찾는다.
- 방 화면 `RoomScreen`(`scenes/room.tscn`): 사람·준비, 판 고르기(방장), 인원(게임 밖에서만). 그림을 다 받아야 준비·시작이 켜진다. 손님이 모두 준비하면 방장이 시작 → `Coop._begin`(call_local) → 모두 3초 카운트다운(뒤에서 장면·그림 미리 읽음) → `Coop.enter`.
- **판 정보는 보내지 않는다**: 협동 직소 새 판은 씨앗 + 화면과 무관한 정사각 탁자(`_scatter_fixed`)로 흩어 모든 기기가 같은 자리에서 시작한다(세로·가로가 달라도). 이어 하는 판만 방장이 상태를 보낸다(`pack_state`, 묶음 배열이라 500조각 6.6KB).
- 인원·게임 중·차단 판단은 **방장 기기**(`CoopRules.admit`), 비밀번호와 돌려보내기는 **서버가 지킨다**: 방장이 비밀번호를 `room` 으로 알리면 DO 가 입장 때 대조하고(방 표엔 안 쓴다), `kick` 은 DO 가 소켓을 끊는다(코드 4002). 고친 앱은 거절을 무시해도 남지 못한다. 근처 방은 서버가 없어 방장 기기 판단뿐이다.
- 게임 중엔 새 사람이 못 들어온다. 방장이 바뀌어 다시 붙는 사람(`_rejoin`)만 예외. 뒤로·판 끝 '방으로': 방장이면 모두 방 화면으로, 손님이면 혼자 먼저 방 화면에서 기다린다.
- 협동 직소 저장은 방장 기기 `user://saves/coop_<그림>_<조각>.json`, 방 화면에 '이어서'로 보인다. 숨은·다른 그림은 저장 안 함(3판 묶음이 짧다).
- 협동 직소 = 300·500·1000조각 (`Stages.COOP_PAINTINGS` 10점). 200조각 넘으면 3D 들어오기를 건너뛴다. 끝까지 시험 `tests/coop_flow.gd`(두 프로세스).
