# 결정 요약

「오잉?」을 만들며 내린 주요 결정과 그 이유. 1인 개발 + AI 에이전트 협업, 날짜순 전체 기록은 비공개 결정 로그에 있다.

## 제품
- **명화 퍼즐 네 가지**: 직소 · 그림 맞추기(슬라이딩) · 다른 그림 찾기 · 숨은 그림 찾기. 혼자(오프라인)와 협동, 겨루기는 같은 판을 모두가 푸는 리더보드 — 숨은·다른 그림은 숙련자에게 점점 쉬워져 1:1 대전이 기운다.
- **명화는 CC0 공개 기관(Met) 이미지만**, 그림마다 출처 JSON. 작품이 퍼블릭 도메인이어도 사진의 권리를 주장하는 곳이 있다.

## AI 콘텐츠 파이프라인: 기기에서 생성하지 않는다
- 휴대폰 생성은 느리고, 기기마다 결과가 다르며, **틀린 판(찾을 수 없는 차이, 그림을 망친 편집)을 걸러 낼 수 없다**. 리더보드는 모두 같은 판이어야 공정하다.
- → 개발 PC 에서 **기획 → 편집 → 자동 검증 → 사람 확인**을 거친 판만 배포. 생성 모델은 연 매출 기준 상업 사용이 되는 라이선스만(FLUX.3 klein, SAM 2.1·LaMa 는 Apache-2.0). 비상업 라이선스 모델(FLUX.1 Fill-dev, AudioGen)은 품질이 좋아도 쓰지 않는다.

| 단계 | 쓰는 것 | 왜 |
|---|---|---|
| 기획 | VLM(Bonsai-2 27B)이 물체·하늘·땅 위치와 장면에 맞는 소품을 제안, 자리·크기는 코드 | VLM 은 '무엇'을 잘 알고 '어디·얼마나 크게'는 코드가 더 믿을 만하다 |
| 그려 넣기 | FLUX.3 klein 이 **그 자리에서** 그리고, 물체 윤곽만 오려 원본 위에 | 물체만 따로 그리면 빛·원근·붓질이 없어 스티커가 됐다 |
| 지우기 | SAM 2.1 로 윤곽 → LaMa 로 그 안만 메움 | 프롬프트 지우기는 흐린 잔상이 남았다 |
| 판정 | VLM 이 '자연스러운가', 지우기는 원본과 나란히 '정말 없어졌나' | 편집본만 보이면 잔상을 '흔적 없음'으로 봤다 |
| 고르기 | 휴대폰 화면 크기에서 실제로 보이는 정도(ΔE 픽셀 수)로 난이도 | VLM 에게 '얼마나 보이나'를 물으면 다 'subtle' 이라 했다 |
| 사람 | 기기에서 검토 후 서명(`verified_by`) | 마지막 책임은 사람 |

## 실패에서 배운 것
- **모델보다 질문**: Bonsai-2 27B(2bit) · Qwen3.8-27B · Qwen3-VL-8B 를 같은 판정 문제로 비교 → 셋 다 4/5, 같은 문제(하늘에 날개 접고 앉은 참새)를 틀렸다. '날개를 펴고 나는가'를 따로 물으니 셋 다 맞혔다. 큰 모델로 바꾸기 전에 질문을 쪼갠다.
- **수치로 못 잡는 건 귀·눈으로**: 생성 배경음악(ACE-Step)의 음정 흔들림은 조율 표류 지표로 구분되지 않았고, 모델을 바꿔도 같았다(파형 생성 모델의 구조적 약점). → 생성 음악을 버리고 퍼블릭 도메인 실제 연주로.
- **자동 검증이 통과시킨 것을 사람이 잡는다**: 잔상 지우기, 허공의 새, 잘린 고양이, 장면에 뜬금없는 소품 — 사람이 짚을 때마다 그 실패를 거르는 규칙(판정 질문, 상자 가장자리 잘림 검사, 장면 소품 질문, 사람 키 기준 크기)을 파이프라인에 넣는다.

## 게임 손맛
- 저사양 기기(LG V30)에서 SubViewport·clip_children·화면좌표 셰이더가 깜빡여 셋 다 버리고 직접 다시 그리기로. 조각당 그리기 17번 → 4번(13 → 34fps).
- 결정론: 직소 판 = 그림 + 조각 수 + 씨앗. 협동은 모양 대신 씨앗과 사건(`grab`/`drop`)만 보낸다.

## 저장소
- 코드·콘텐츠는 비공개, 기획·결정 노트 중 공개할 것만 이 저장소로 내보낸다(`publish: true`). 미디어(그림·음악)는 git 밖 — 출처 JSON 만 기록하고 파일은 다시 받거나 묶음으로 보관.
